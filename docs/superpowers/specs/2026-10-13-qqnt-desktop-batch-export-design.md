# QQNT 聊天记录桌面批量导出设计

日期：2026-10-13

## 1. 目标与范围

为现有 qqnt-chat-export 增加面向普通 Windows 用户的图形界面。用户打开已登录的 QQ 后，在界面中找到可导出的私聊和群聊，选择多条会话，指定非系统盘目录，批量生成适合 LLM 阅读的 UTF-8 Markdown 和 JSON。保留现有命令行入口。

首版支持当前适配器确认的 Windows QQ 9.9.27。兼容性检查失败时停止并给出安全提示，不猜测其他版本的数据库结构或密钥。参考 WeFlow 的会话列表、筛选、批量选择和任务反馈等通用交互思路。界面代码、控件、配色、图标和素材独立制作，不复制 WeFlow 的实现或资源；项目现有 MIT 许可保持不变。

## 2. 用户流程

1. 启动便携式 Windows 程序目录中的可执行文件，无需安装 Python。
2. 程序发现本机 QQ 数据源并显示兼容状态。多个账号或进程时由用户选择；也可手动指定数据库或 Tencent Files 根目录。扫描前展示可修改的临时工作位置。
3. 用户主动扫描会话。列表支持按名称或选择值搜索，以及“全部 / 私聊 / 群聊”筛选；只显示标题、类型和消息数，不显示聊天正文。
4. 用户逐项勾选或全选当前筛选结果。切换筛选条件不会清除已选会话。底部固定显示已选数量和“导出所选”。
5. 确认窗口中选择非系统盘输出目录，确认同时生成 Markdown 与 JSON。界面展示阶段进度、逐会话状态和最终结果，并提供“打开输出目录”。

原始 QQ 数据库可以位于系统盘。工作目录与导出目录必须位于非系统盘。程序优先选择空间足够的非系统盘作为临时工作位置并在界面显示；没有合适位置时要求用户选择，验证路径与可用空间后才允许扫描。首次打开不自动复制数据库。首版不保存数据库密钥、聊天正文、会话索引、上次账号、源路径、工作目录或输出目录。

## 3. 界面与视觉

使用 PySide6 Widgets 构建 Windows 桌面界面。主窗口沿用已确认草图的信息层级：窄侧栏仅含“导出聊天记录”和“使用说明”；顶部显示数据源状态与重新扫描；中部是搜索、私聊/群聊筛选及多选会话表；底部固定主操作。数据源未就绪、扫描中、无会话、失败、导出中和完成都有明确状态。

视觉采用独立设计的深蓝灰背景、清晰的卡片边界和蓝色主操作。文字与控件在 Windows 125% 和 150% 缩放下可读；列表支持键盘操作，焦点与禁用状态可辨认。公开截图和测试只用虚构数据。导出确认窗口只提供目录与选择摘要，首版固定同时生成两种格式。

## 4. 组件与数据流

**桌面界面：**负责数据源选择、扫描、筛选与勾选、确认、进度、取消和结果。界面不直接拼 SQL、读取进程内存或操作数据库文件。扫描与导出在后台工作线程运行，通过信号向主线程发送进度和结果；只在主线程更新控件。

**共享应用服务：**从现有 CLI 提取可复用的会话扫描和批量导出服务。CLI 与 GUI 调用同一套发现、兼容检查、快照、解密、结构校验、解析和导出能力。服务接收明确的数据源、输出目录、进度回调和可查询的取消标记，返回会话索引或逐会话结果。

扫描和导出是两个独立任务。扫描使用界面确认的临时工作位置，创建自己的只读快照和解密副本，读取索引后关闭连接并清理工作目录；用户在列表停留时不保留明文库。导出重新创建快照，在同一个已校验连接中处理本批次全部会话，避免逐条重复复制和解密。导出前重新核对所选会话；消失的会话标记失败，继续其他项。

**打包：**使用 PyInstaller 目录模式构建 Windows x64 便携式程序，包含可执行文件、PySide6 与经验证的解密依赖。目录模式避免单文件程序每次启动向系统盘临时目录解压大型依赖。构建输出放非系统盘，发布包附第三方许可证说明。源码仍可安装可选 GUI 依赖；CLI 不强制安装 PySide6。

## 5. 输出与隐私

原始 nt_msg.db 及 WAL、SHM 始终只读。扫描和导出先复制到非系统盘的带所有权标记工作目录，检查复制期间是否变化；只对副本解密和查询。成功、失败和取消后都关闭连接并按现有安全规则清理副本。无法确认所有权时保留目录并提示手动检查，不扩大删除范围。

每次批量导出在用户指定位置创建唯一的本次导出目录，避免覆盖历史结果。每条会话沿用哈希化私聊或群聊子目录，包含 chat_export.md、chat_export.json 和脱敏的 export_report.json。已完整导出的会话在后续失败或取消时保留；未完成会话的临时文件清理，不留下看似成功的半成品。列表和结果页可在本地显示标题；终端、诊断报告和异常日志不得包含 QQ 号、昵称、正文、密钥、原始 BLOB 或含身份信息的绝对路径。

继续沿用现有解析规则：只输出已确认文本；媒体用已知类型标记，未知或损坏结构标成“未识别消息结构”，JSON 只保留有界结构信息，不猜正文。GUI 和 CLI 使用相同的 Markdown 与 JSON 记录格式。

## 6. 取消、错误与恢复

任务运行时禁用重复启动。取消为协作式：在阶段边界和消息写入循环中检查标记，尽快停止当前未完成会话及后续会话，清理临时文件和工作目录。用户关闭窗口时若仍有任务，先请求取消并等待安全收尾，再退出。

数据源不存在、QQ 未登录、版本不支持、系统盘输出、空间或权限不足、复制中数据库变化、解密失败、结构不匹配分别展示安全的可读提示。扫描失败不展示旧索引。批量导出中单条失败时记录该项并继续，最终显示成功、失败和取消数量。意外异常仅显示通用错误及不含私人内容的技术状态。

## 7. 验收与验证

- 用合成数据验证扫描、搜索筛选与勾选、批量导出只做一次快照、重新核对、部分失败、取消、原子写入、非系统盘限制及安全清理。
- 验证耗时任务不冻结窗口、进度只在主线程更新，以及关闭窗口时工作线程安全结束。
- 保持现有 CLI 行为与文件格式，并运行全量测试。当前基线是 54 项中 53 项通过；1 项打包测试因本机缺少可执行的 python -m build 环境而失败，需在实现阶段修复测试环境后再判定回归。
- 在 Windows x64 上构建目录模式程序，验证无 Python 环境启动、QQ 9.9.27 数据源发现、合成数据库完整导出，以及输出和临时文件位于非系统盘。真实聊天数据只在本机私下验证，不进入测试夹具、截图或仓库。

## 8. 首版不包含

年度分析、统计图表、聊天正文浏览、媒体文件解密与导出、自动同步、云服务、遥测、跨平台安装包，以及对其他 QQ 版本的猜测适配。
